Semantic Caching Layer for LLM APIs

Project Overview Document  |  August 2026

1. What This Project Is About

This project is a middleware caching service that sits between your application and any LLM provider (OpenAI, Ollama, etc.). It detects semantically similar requests that have already been answered and serves cached responses instantly — cutting latency to near-zero and reducing API costs by 30–60% on typical workloads.

Key Idea: Instead of exact string matching, the cache uses vector embeddings to understand the meaning of prompts. So "What is Python?" and "Explain Python to me" are recognized as the same question and served from cache.

Core Features

  • Semantic Similarity Matching — Embeds prompts into 384-dimensional vectors and uses cosine similarity to find matches
  • Drop-In Proxy API — Mirrors the OpenAI Chat Completions API exactly; switch by changing the base URL, zero code changes
  • Multi-Provider Routing — Auto-detects whether to route to OpenAI or Ollama (local, free) based on the model name
  • TTL Auto-Classification — Automatically assigns cache lifetimes: 24h for factual queries, 1h for time-sensitive ones, skip for creative prompts
  • Adaptive Thresholds — Adjusts similarity thresholds per task type (classification=0.90, QA=0.93, creative=0.98)
  • Threshold Tuner — Visualizes the tradeoff between cache hit rate and accuracy at different thresholds
  • Cache Invalidation — Selective invalidation by system prompt, model upgrade, or prompt prefix
  • Streaming Support — Simultaneously streams responses to the client while buffering for cache storage

2. What Problem It Solves

Every company running LLMs at scale faces the same problem: redundant API calls burning money and adding latency. In real-world applications, 30–60% of LLM queries are semantically identical to previous ones.

Problems Addressed

Problem How This Project Solves It
High API Costs
Each LLM call costs money (GPT-4o ~ $5/1M tokens)		 Cache hits return instantly at zero cost. Repeated and similar queries never hit the paid API twice.
High Latency
LLM calls take 1–10 seconds each		 Cache hits return in under 5ms — sub-millisecond similarity search via NumPy vector operations.
Exact Match Fails
Traditional caches miss "What is Python?" vs "Explain Python to me"		 Semantic embeddings understand meaning, not just characters. Both prompts map to similar vectors.
Stale Cache Entries
Time-sensitive answers go stale		 TTL auto-classifier assigns different lifetimes based on content type. Weather queries expire in 1h, definitions last 24h.
One-Size-Fits-All Threshold
Different tasks need different similarity tolerances		 Adaptive thresholds auto-detect task type and adjust. Classification tasks tolerate lower similarity; creative tasks require near-exact matches.
Vendor Lock-In
Tied to a single LLM provider		 Provider-agnostic design. Route to OpenAI, Ollama, or add new providers with a single class.

3. Tech Stack

Component Tool / Library Why This Choice
Language Python 3.13+ Ecosystem compatibility, ML library support
Embeddings sentence-transformers
all-MiniLM-L6-v2		 Free, local, no API key needed. Produces 384-dim vectors. Fast inference on CPU.
Vector Store NumPy (in-memory) Zero infrastructure. Brute-force cosine similarity via matrix dot product. Swappable for Redis/Qdrant later.
Proxy Layer FastAPI + Uvicorn Async, high-performance, auto-generated OpenAPI docs. Drop-in API replacement for OpenAI.
HTTP Client httpx Async HTTP for calling LLM providers. Supports streaming SSE responses.
LLM Providers OpenAI API + Ollama OpenAI for production. Ollama for free local development with open-source models (Llama, Qwen, etc.).
Configuration Pydantic Settings Type-safe config with environment variable overrides (SEMCACHE_ prefix).
Data Models Pydantic v2 Validates all request/response payloads. Mirrors OpenAI's JSON schema exactly.
Testing pytest 42+ tests across 3 phases. Covers similarity matching, TTL classification, invalidation, and threshold analysis.
Cache Policy Custom TTL + keyword classifier Auto-assigns TTL tiers (24h / 6h / 1h / skip) based on prompt content analysis.
Threshold Tuning Custom threshold tuner Records lookup history. Replays at different thresholds to find the optimal hit-rate vs accuracy balance.
